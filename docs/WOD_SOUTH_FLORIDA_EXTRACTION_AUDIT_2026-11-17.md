## Format observation requiring resolution

The decompressed content is fixed-width WOD-like ASCII, not NetCDF: 80-byte records with CRLF separators and repeated multi-line cast blocks. Each cast-start line begins with `Q` (861 GLD, 3 MRB, 200 PFL, 3,725 MBT, 2,286 XBT).

The WOD23 User Manual describes 80-character ASCII records and states that the first byte is `C` for WOD23/WOD18, `B` for WOD09/WOD05, and `A` for WOD01. The observed `Q` marker therefore does not match the documented release markers. The query's WOD release/version and selected export format were not preserved in the copied query criteria, so do not assume these files are confirmed WOD23 native-format files. Resolve the marker against the exact WODSelect export/version or NOAA's sample reader before parsing.

### Resolution of the Q prefix

The `Q` prefix is not an unexplained NOAA corruption or a reason to reject the archive. Inspection of the IQuOD `wodpy` reference parser (`IQuOD/wodpy`, `wodpy/wod.py`) shows explicit detection of a first-line `Q` marker as IQuOD formatting (`self.IQuOD = True`). The parser then reads additional latitude/longitude uncertainty fields, per-variable and secondary-header `iMeta` fields, per-level depth uncertainty, and per-variable value uncertainty. This is the missing format distinction that the standard WOD23 ASCII description alone did not explain.

## Clarification: current NOAA code table confirms GLD auxiliary position/time variables | 2026-11-18

A follow-up check of the current NCEI online depth-dependent-variable code table resolves the apparent dataset-availability discrepancy. Unlike the 2024 WOD23 manual's prose summary, the current online table explicitly lists codes 30 (latitude), 31 (longitude), and 32 (Julian year-day) for GLD as well as SUR/APB/UOR. Its footnote says these codes are not depth-dependent variables and are not selectable in WODSelect.

Therefore their presence in the GLD archive is supported by the current code table and is not a format error. In this archive, 116 casts carry these values aligned with profile levels, and the decoded latitude/longitude values vary along the glider trajectory. Treat them as per-observation position/time metadata, not physical variables that depend on depth. The 745 remaining casts contain code 32 but no per-level latitude/longitude, so their primary-header coordinates remain the available spatial locator. Use the per-observation coordinates for the 116 casts after basic consistency checks; retain the source distinction in the normalized data.
